## 2. Face probe — the one clear win

Conditioning on `face_px` is worth more than everything I did in fusion.

```
so_fake_ood, face-present rows
                  clean    worst  variant     drop
baseline (768-d) 0.8952   0.8620  noise01   0.0332
face.py  (769-d) 0.9382   0.9151  noise01   0.0231
```

The ablation reproduces the documented baseline exactly (0.8952 / 0.8620), which is
what makes the comparison trustworthy — same data, same split, only the 769th
feature differs.

Box sizes run 64–612px, so the feature is standardised `log2(face_px)`: the effect
is a ratio, not a difference, and a raw column on that scale would swamp the L2
penalty against unit-norm embeddings.

## 4. The finding that matters

Fusion **does** beat the general probe and clear the SPEC Phase-5 gate — but only
when calibrators and the meta-classifier are fitted on generator-diverse data.
Fitted on `sid_calib`, as the spec mandates, it loses.

### Why `sid_calib` breaks it

It shares generators with train, so general scores **0.9995** there. Platt fitted on
a saturated branch learns an extreme slope, and that slope manufactures
over-confidence the moment a new generator appears.

The clearest way to see it is to sort the branches by how saturated they were on
the set they were calibrated against. **How much a branch's calibration collapses
is predicted by how little room it had to be wrong.**

```
branch     AUC on cal set   ECE in  ECE out  factor
general            0.9995   0.0022   0.1085   49.5x
face               0.9985   0.0143   0.1697   11.9x
tampered           0.9636   0.0062   0.0112    1.8x
spectral           0.6807   0.0520   0.0741    1.4x
```

The two branches above 0.998 blow up 12–50x. The two below 0.97 barely move.
Tampered is the control that proves it: same Platt code, same grid, but calibrated
against a question it does not ace, and it transfers almost perfectly.

So this is not "calibration does not survive distribution shift". It is
**calibrating a saturated branch manufactures the over-confidence** — which is a
fixable data problem, and §6 is the fix.

Diagram: `docs/figures/reliability.png`, regenerated by `python -m quorum.fusion`.

`sid_calib` also contains **zero tampered images** — 2,000 real / 1,996
full_synthetic — so fusion never observes the one case where general is not merely
wrong but inverted.

### With a generator-disjoint split, fusion wins

So-Fake-OOD carries **15 labelled generators**. Calibrating on half, evaluating on
the unseen half, five random partitions:

```
split  fusion  general   d_clean   d_worst
    0  0.9218   0.9172   +0.0046   +0.0035
    1  0.9026   0.8984   +0.0041   +0.0086
    2  0.9410   0.9350   +0.0061   +0.0104
    3  0.9352   0.9303   +0.0050   +0.0045
    4  0.9106   0.9094   +0.0013   +0.0005
 mean                    +0.0042   +0.0055
```

Positive on all five, on both clean and worst.

## 5. Adriel was right about sequencing

He said do the models first, since fusion is downstream of their outputs. I tested
it by giving fusion an oracle — fitting it on the eval set itself, which is cheating
and therefore an upper bound on what any fusion work could ever buy.

```
fusion, honest (5-split mean)      +0.0042
fusion, in-sample oracle (ceiling) +0.0140
face.py, one added feature         +0.0430
```

A *perfect* fusion is worth about a point and a half. One feature on one branch was
worth four and a third. Branch work has roughly three times the headroom of an
unbeatable meta-classifier, so the priority call is correct.

Two caveats on sequencing:

- Fusion is not competing for anyone's time — it is already built.
- The calibration problem is independent of model quality. Better branches will not
  fix a saturated calibration set, so the carve in §6 is worth doing in parallel
  rather than after.

`noise01` loses 15–18%, not 77%. `resize025` loses 0–6%, not 15%.

This matters because the survivorship story rests on it. Face AUC rises under blur
(0.9382 clean → 0.9500 at `blur20`), and we explained that as the detector dropping
marginal faces first. But `blur20` retains 99.7% of them — almost nothing drops out,

not yet know what. Worth chasing, since "our face branch improves under blur" is a
claim we would have to defend under questioning.

Separately: `crop08` reliably *finds more* faces than clean, on every source.

**`pull_cache.py` rewrites every tracked manifest CSV to CRLF.** The shards were

## 7. Albert — general and spectral

**Spectral is the highest-leverage branch left.** It is the weakest signal
(0.56–0.74) and it is weak in exactly the places general is weak, so it is where
fusion has the most to gain. Improving general moves the number that is already
strongest.

**`spec_so_fake_ood` holds 25 all-zero feature vectors** — 3 distinct images, all
label 0, spread across roughly 8 variants each. The other four spectral sources have
none. A zero vector is not a missing branch: it flows through as a real score rather
than tripping the presence-flag path, so those three images get neither a signal nor
an abstention. Your file, your call on where the guard belongs.

## 8. Decisions I took

- **Text branch: cut.** Nine hours of OCR for a seven-parameter model, against fusion
  being the critical path. The two slots stay in the vector at neutral fill, so
  wiring it back is a one-line change. TextFake still belongs in the README
  limitations — it undercuts the "garbled signage is high precision" premise, since
  GPT-Image renders text well and is the hardest generator to catch.
- **Calib split in two**, by `image_id` so all 15 variants of an image stay on one
  side. Calibrators fit on `calib_a`, fusion on `calib_b`.
- **Tampered kept out of the fusion objective**, on the measurement in §3.

## 9. One thing worth saying out loud

A single CLIP probe scores **0.91** on unseen generators and **0.37** on locally
edited photos — worse than chance, because a tampered photo is globally authentic.
No amount of tuning one probe fixes that, and no branch improvement will either: the
general probe is *correct* about what it sees.

That is the sharpest argument the ensemble has, and a better pitch than a marginal
AUROC bump. It is also most of the required error-analysis note already written.
